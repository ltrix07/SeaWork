# Карта: E2.1 эталон пар «профиль × вакансия» (30–50 пар, команда оценки согласия Match Score)
## Точки входа
- src/seawork/scoring/engine.py:49 `compute_match_score(profile, opportunity, *, factors=FACTORS, now=None) -> MatchScore`: чистая функция, без БД и сети
- src/seawork/recommendation/engine.py:28 `recommend(...)`: единственный потребитель value (ранжирование); вызывает compute_match_score на каждом кандидате
- src/seawork/storage/repository.py:185 `Repository.list_feed_candidates() -> list[Candidate]`: единственный путь вакансия из БД -> Candidate (ACTIVE, не source_trashed)

- scripts/check_eval_gold.py:main: валидатор эталона (образец); src/seawork/reporting/enrichment_eval.py: метрики и отчёт (образец)
## Поток
digest/bot -> list_feed_candidates -> to_enriched(record) (repository.py:16) -> recommend -> compute_match_score -> 8 факторов (scoring/factors.py:373) -> _value (engine.py:34) = matched_weight / comparable_weight.
Eval match (будущее): yaml -> UserProfile + EnrichedOpportunity (model_validate) -> compute_match_score -> value -> сравнение с меткой.
## Контракты
- MatchScore (domain/match.py:44): value float|None [0..1], comparable_factors int, verdicts list[FactorVerdict], computed_at, profile_fingerprint, opportunity_fingerprint. FactorVerdict: factor, outcome(match|mismatch|not_comparable), weight, *_evidence, *_confidence, caveats list[str]. Модели frozen.
- Факторы по порядку (factors.py:373), имена вердиктов: profession, direction, languages, experience, certificates, country, hiring_country, career_goal. Все равновесны.
- Веса: ТОЛЬКО scoring/weights.py: BASE_WEIGHT=1.0 на фактор; weight = 1.0 * opp_conf * profile_conf (None -> 1.0), NOT_COMPARABLE -> 0 (weights.py:23-39). Калибровать = менять этот файл (и/или передавать `factors=`; per-factor таблицы нет).
- UserProfile (domain/profile.py:100): user_id UUID, created_at, updated_at обязательны; остальные Fact[...] | None. Fact(value, source STATED|OBSERVED|IMPORTED, confidence, stated_at); STATED требует confidence==1.0 (profile.py:70). Влияют на оценку: career_stage (CareerStage undecided|entry|working|experienced), professions, directions, certificates, languages, preferred_countries, hiring_country (все Fact[list[str]]), career_goal (Fact[CareerGoal(profession|direction|country, минимум одно)]). residence_country, citizenship, work_authorization в оценке НЕ участвуют (grep factors.py).
- Минимальный профиль без БД: `UserProfile.model_validate({"user_id": uuid4(), "created_at": T, "updated_at": T, **facts})`, где facts = {"career_stage": Fact(value=..., source=STATED, confidence=1.0)}; образец tests/test_match_score.py:29-58 (хелперы stated/profile/vacancy/inferred). Для YAML: {value, source, confidence} словарь валидируется model_validate как есть.
- Словари ключей: data/reference/{professions,directions,certificates,languages}.yaml (поле `key`), страны ISO alpha-2 только по форме `[A-Z]{2}` (storage/profile_vocabulary.py:35,56). Проверка словарей делается при записи в БД (ProfileVocabulary.check, vocabulary.py:~75), у голой UserProfile.model_validate её НЕТ: валидатор эталона должен делать её сам, `ProfileVocabulary.from_directory(reference_dir)` годится как есть.
- Вакансия (domain/models.py:63 EnrichedOpportunity): обязательны normalized(source_id, external_id, url, title), type, type_confidence, quality_score, quality_flags. Для оценки читаются: profession, direction, required_languages, experience_level (ExperienceLevel entry|junior|mid|senior|lead), required_certificates, country, hiring_scope (Inferred[HiringScope(anywhere, countries, unresolved)]), type (internship снимает сертификат, factors.py:263), normalized.recruitment_office_raw (только как evidence). Inferred(value, provenance source|rule|llm, confidence, quotes).
## Сериализация вакансии в фикстуру (ответ на п.3)
- enrichment_gold.yaml хранит НЕ payload и НЕ EnrichedOpportunity: source_id, external_id, stratum, url, title, text (поле text) + ручные метки. Предсказание в эталоне не хранится: LLM прогоняется заново по text (enrichment_eval.py), так что там это и нужно.
- Для match-gold text недостаточен: оценка читает уже ОБОГАЩЁННЫЕ поля. Хранить в фикстуре `opportunity.model_dump(mode="json")` EnrichedOpportunity целиком: round-trip `EnrichedOpportunity.model_validate(dict)` без БД проверен конструкцией (Repository пишет то же через model_dump(mode="json"), repository.py:88, и читает через model_validate, repository.py:17). Все вложенные типы (HttpUrl, Decimal, datetime, StrEnum) сериализуются/читаются из JSON-подобного словаря.
- Сложность: в БД normalized хранится урезанным (repository.py:20-28: нет location_raw, recruitment_office_raw, salary_raw, language, declared_type, source_fields), поэтому `to_enriched(record)` и dump с живого кандидата дают ту же урезанную форму, что видит продакшен-выдача; брать дамп именно с `Candidate.opportunity` (то, что реально скорится), не с ингеста (отпечатки различаются, recommendation-engine.md:186). Следствие: evidence hiring_country без recruitment_office_raw пустое, на значение не влияет.
- Заморозка снимка: дамп один раз скриптом (аналог build_eval_sample.py: sys.path.insert, свой main) с `list_feed_candidates()`, поля: opportunity_id (для ссылки), source_id, external_id, url, title, `opportunity` = dump. Вручную размечать нужно по title/description/полям, поэтому в yaml полезно положить читаемую выжимку (title, employer, description) рядом с dump. Эталон не зависит от живой БД и от повторного обогащения (но замораживает ошибки обогащения: это нужно оговорить в заголовке эталона).
## Инварианты
- NOT_COMPARABLE исключается из знаменателя; value=None при total weight<=0 (engine.py:34-48); None != [] у профиля (certificates/languages [] = «не имею» -> MISMATCH; professions/directions/preferred_countries/hiring_country [] = нет предпочтения).
- entry -> только experience_level entry (решено владельцем 12.10.2026); недоопределённый stage `undecided` несравним (factors.py:42-49,310).
- Нет жёстких фильтров; единственное исключение в recommend: value==0.0 исключается (recommendation/engine.py:42), dismissed/delivered тоже.
- Ярусы в recommend: ключ (value is None, -value, -comparable_factors, свежесть, id), затем круг по direction внутри яруса с ОДИНАКОВЫМ (value, comparable_factors) (engine.py:62-70,119). Порог 85% в коде отсутствует (grep); в recommendation-engine.md:76 «других порогов нет». Следовательно осмысленные метрики: (а) порядок внутри профиля (ранговая корреляция/ pairwise accuracy по меткам fit>спорно>нет), (б) разделимость: пара «подходит» против «не подходит» (AUC) и порог value==0.0, (в) value=None как отдельная корзина, считать отдельно (доля None, метки на них). Абсолютное соответствие value и процента неинтерпретируемо до калибровки. Метка «спорно» разумно исключать из бинарных метрик и показывать отдельно.
- Эталон должен фиксировать `now` не нужно (value от времени не зависит); computed_at и fingerprints в метрике не используются.

## Риски / нельзя трогать
- Не менять веса/BASE_WEIGHT/_STAGE_LEVELS и пороги в этой задаче: E2.1 только измеряет; weights.py прямо запрещает подгонку под примеры.
- Не размечать эталон моделью (так же, как enrichment_gold): метки «подходит / не подходит / спорно» ставит владелец. Профили эталона фиксированные (3-6 штук разных stage/direction/страны), пары перекрёстные; профили должны включать пустой и неполный случаи, иначе value=None не измерить.
- Не брать данные из Candidate по живой БД в самой команде оценки (иначе эталон плывёт); не менять формат БД и миграции (0001–0008).
- Метки зависят от того, что видит человек: размечать по тем же полям, что получает скорер, иначе эталон требует невозможного (то же, что в шапке enrichment_gold.yaml).
- Вопрос в recommendation-engine.md:88,203: «неизвестное против слабого совпадения» ответит этот эталон; в оценку это не вшивать.
