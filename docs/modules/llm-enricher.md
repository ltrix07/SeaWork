# Контракт: LLM-обогатитель

> Реализует `ingestion/enrich/llm.py` как вторую реализацию `Enricher` рядом с `RulesEnricher`
> Основание — `docs/milestone-1-report.md` §5; тарификация — `docs/ai-cost-boundary.md`

---

## 1. Зачем и где границы

Веха 1 показала потолок детерминированных правил на 251 вакансии:

| Поле | Правилами | Почему не больше |
|---|---:|---|
| `profession` | 98.8% | — правила справляются |
| `salary` | 100% там, где источник даёт | — |
| `experience_level` | 45.0% | остальное записано качественно: `experience in rank and on similar vessel type` |
| `required_certificates` | 48.2% | часть требований прозой, без узнаваемых аббревиатур |

**Модуль обрабатывает ровно два поля: `experience_level` и `required_certificates`.** Всё остальное правила закрывают лучше, быстрее и бесплатно.

### Не входит

- поля, где правила справляются (`profession`, `direction`, `salary`, `country`, `type`);
- любые пользовательские AI-функции — AI Summary, объяснения, консультант, разбор CV. Это другой слой с другой экономикой и другими требованиями по резидентности данных, см. `docs/ai-cost-boundary.md`;
- переписывание или «улучшение» описаний.

### Когда вызывается

Только для записей, где `RulesEnricher` вернул `None` хотя бы по одному из двух полей. На снапшотах это 189 из 251 записи (75.3%): `experience_level` пуст у 138, `required_certificates` — у 130, множества пересекаются частично. Одного вызова хватает на оба поля.

**Из них 17 записей не имеют пригодного текста** (короче 20 значимых символов после нормализации) — у них пуст и раздел квалификаций, и описание. Такие записи **пропускаются без вызова модели**: читать нечего, и единственный корректный ответ известен заранее. Обнаружено при подготовке эталона (§7).

Итого модель вызывается для **188 записей из 251** (74.9%).

## 2. Архитектурные решения

Обязательны к соблюдению. Если реализация вынуждает их нарушить — остановиться и вынести вопрос.

### 2.1 Модель обязана уметь сказать «не знаю»

Схема ответа и промпт **явно разрешают** значение «не определено», и оно отображается в `None`.

Это главное решение всего модуля. Языковая модель по умолчанию отвечает на любой вопрос — если не дать ей выход, она выдаст правдоподобную догадку, неотличимую от факта. Половина обрабатываемых записей действительно не содержит требуемой информации, и правильный ответ для них — пустота.

Прямое следствие `ingestion.md` §3.3: ненайденное — это `None`, а не заполненное значение.

### 2.2 Цитата-подтверждение и её проверка

Модель обязана вернуть **точную подстроку исходного текста**, на которой основан вывод. Реализация **проверяет наличие этой подстроки в источнике** после нормализации пробелов.

Цитата не найдена → значение отбрасывается, поле становится `None`, событие логируется как `llm_quote_not_found`.

Это самый дешёвый и надёжный из доступных барьеров против выдумывания: модель, сочинившая требование к опыту, не сможет предъявить фрагмент текста, которого нет. Стоит несколько выходных токенов.

### 2.3 Основание вместо самооценки уверенности

Модель **не оценивает свою уверенность числом** — такие самооценки плохо откалиброваны и создают ложное ощущение точности.

Вместо этого возвращается дискретное основание:

```
stated    — требование сформулировано в тексте прямо ("Minimum 2 years experience")
inferred  — выведено из формулировки ("experience in rank on similar vessel type")
```

Отображение в нашу модель:

| basis | provenance | confidence |
|---|---|---|
| `stated` | `LLM` | 0.9 |
| `inferred` | `LLM` | 0.6 |

Числа выбраны так, чтобы `inferred` заведомо уступал любому факту источника (1.0) и правилу (0.9). Калибруются по результатам оценки §7.

### 2.4 Валидация без исправления

Значение вне нашего `ExperienceLevel` или ключ вне `certificates.yaml` — **отбрасывается**. Никакого нечёткого сопоставления, приведения регистра, поиска ближайшего.

Модель, вернувшая `senior-ish` или выдуманный ключ сертификата, ошиблась; «починив» её ответ, мы получим уверенно неверные данные вместо честной пустоты.

### 2.5 LLM никогда не перезаписывает источник и правило

Обогатитель дополняет только `None`. Значение с `provenance=SOURCE` или `RULE` не меняется ни при каких условиях.

По построению конфликта не возникает: LLM вызывается лишь там, где правило ничего не нашло. Инвариант всё равно проверяется тестом — чтобы будущая правка порядка стадий не сломала его молча.

## 3. Провайдер — параметр конфигурации, а не решение

Провайдер задаётся конфигурацией. Прибивать его к коду запрещено.

```python
class LLMClient(Protocol):
    model_id: str
    async def extract(self, prompt: str, schema: dict[str, object]) -> dict[str, object]: ...
```

Причина: по итогам замеров (`docs/ai-cost-boundary.md` §7) стоимость перестала быть решающим фактором — разница между кандидатами составляет единицы-десятки долларов в месяц. Решать должно **измеренное качество на нашем снапшоте**, а его нельзя узнать заранее.

Рассматриваемые кандидаты и их стоимость на всём корпусе из 251 записи:

| Провайдер | Разово | 500 вакансий/день |
|---|---:|---:|
| DeepSeek V4 Flash | $0.019 | $1.11/мес |
| Anthropic Haiku 4.5 | $0.170 | $10.15/мес |
| Anthropic Sonnet 5 | $0.340 | $20.31/мес |

**Отдельный провайдер для пользовательского слоя.** Инфраструктурное обогащение работает с публичными объявлениями — персональных данных нет. Пользовательские AI-функции (разбор CV, SPEC.md §3.5) обрабатывают резюме европейских пользователей, и передача их за пределы ЕС регулируется главой V GDPR. Архитектура обязана допускать двух разных провайдеров; выбор для второго слоя — отдельное решение, принимать его по инерции от этого нельзя.

## 4. Схема ответа

```json
{
  "experience_level": {
    "value": "entry|junior|mid|senior|lead|null",
    "basis": "stated|inferred",
    "quote": "точная подстрока исходного текста"
  },
  "required_certificates": [
    { "key": "stcw", "basis": "stated", "quote": "valid STCW certificate" }
  ]
}
```

- `value: null` и пустой список — **штатные, ожидаемые ответы**, а не ошибка;
- при `value: null` поля `basis` и `quote` отсутствуют;
- ключи сертификатов — только из `data/reference/certificates.yaml`, список передаётся в промпте;
- использовать структурированный вывод провайдера (constrained decoding), а не просьбу «ответь JSON-ом». При отсутствии такой возможности — валидация с одним ретраем, затем отказ.

## 5. Промпт

Требования к содержанию:

1. Роль: извлечение из текста требований морской вакансии.
2. **Явное разрешение не отвечать**: «Если в тексте нет требования к опыту — верни `null`. Отсутствие требования это нормальный и частый случай. Не угадывай».
3. Различение `stated` и `inferred` с примерами обоих.
4. Полный список допустимых ключей сертификатов.
5. Требование дословной цитаты из входного текста.
6. Запрет на извлечение из посторонних контекстов: срок контракта (`Contract Duration: 5 months`), периодичность переаттестации (`Food Hygiene course every 2 years`), тип судна. На этих формулировках спотыкались правила — модель споткнётся о них тем же образом.

Промпт версионируется константой `PROMPT_VERSION`. Она входит в ключ кэша (§6) — иначе после правки промпта будут возвращаться ответы, полученные по старой формулировке.

## 6. Режим выполнения и кэш

### Batch API как основной режим

Обогащение при загрузке не чувствительно к задержке, а батч даёт **−50%** к стоимости и обычно отрабатывает в пределах часа. Синхронный режим — только для отладки и разовых прогонов; переключается конфигурацией.

### Кэш результатов

Ключ: `(content_hash, prompt_version, model_id)`.

Все три компонента обязательны. `content_hash` не даёт платить повторно за тот же payload при `reprocess` — прямое следствие `ingestion.md` §3.1. Версия промпта и идентификатор модели обязаны входить в ключ, иначе после смены промпта или модели система будет молча отдавать старые ответы, и результаты оценки §7 окажутся недостоверными.

### Prompt caching не применять

Минимальный кэшируемый префикс у Anthropic — 2048 токенов (Sonnet) и 4096 (Haiku 4.5, Opus 4.8). Наш системный промпт со схемой около 400 токенов, то есть на порядок ниже порога: кэш не создастся, причём молча, без ошибки. Закладывать на нём экономию нельзя.

### Отказоустойчивость

- таймаут и ограниченное число ретраев; при исчерпании — поля остаются `None`, объект сохраняется, событие логируется;
- **недоступность LLM не должна ронять пайплайн**: правила уже отработали, их результат ценен сам по себе;
- ограничение параллелизма и уважение к rate limit провайдера.

## 7. Оценка качества — обязательный артефакт

Без неё модуль подключать нельзя: иначе мы заменим измеримую пустоту на неизмеримую догадку.

**Эталон.** 50 записей в `tests/fixtures/eval/enrichment_gold.yaml`, размечаются вручную.

Заготовка генерируется `scripts/build_eval_sample.py` — детерминированно (фиксированный seed), пересобирается и диффится. Выборка стратифицирована по механическим признакам: источник × упоминание опыта × упоминание чего-либо сертификатоподобного. Признаки коррелируют со сложностью, но не содержат суждения — суждение и есть работа человека.

Страта **`no-signal`** (текст не содержит ни слова об опыте, ни признаков сертификатов) **намеренно перевзвешена** — 13 записей из 50 при доле около 9% в популяции. Это и есть тест на ложные заполнения, а он важнее остальных.

Фактический состав: 27 Pinpoint, 23 Crewplanet.

**Размечать эталон моделью запрещено** — иначе измеряется согласие модели с самой собой, а не точность. Определить, что `experience in rank and on similar vessel type` означает средний уровень, а не начальный, может только человек, знающий отрасль.

**Команда:** `seawork eval enrichment --provider <name>`

**Отчёт по каждому полю:**

- точность (доля верных среди заполненных);
- полнота (доля заполненных среди тех, где эталон содержит значение);
- **доля ложных заполнений** — случаи, когда эталон пуст, а модель что-то вернула;
- срабатывания проверки цитаты;
- разбивка по `basis`.

**Главная метрика — доля ложных заполнений.** Пропущенное требование стоит одной несостоявшейся рекомендации. Выдуманное требование к сертификату отправит пользователя тратить деньги и месяцы на курс, который ему не нужен, — и подорвёт доверие, которое SPEC.md §8.8 называет стратегической целью продукта. Эти ошибки несимметричны, и метрика обязана это отражать.

**Порог подключения:** доля ложных заполнений не выше 5%. При превышении — правится промпт, а не порог.

Прогон делается **для каждого провайдера-кандидата на одном эталоне**. Выбор — по этой таблице, а не по цене.

## 8. Тесты

- фикстуры записанных ответов провайдера в `tests/fixtures/llm/`, все тесты офлайн, без сети;
- **обязательный тест на §2.2**: ответ с цитатой, отсутствующей в исходном тексте, даёт `None` и запись в лог;
- **обязательный тест на §2.1**: `value: null` корректно проходит весь путь и не превращается в значение по умолчанию;
- **обязательный тест на §2.4**: значение вне enum и неизвестный ключ сертификата отбрасываются, а не исправляются;
- **обязательный тест на §2.5**: поле с `provenance=RULE` не перезаписывается;
- тест на ключ кэша: смена `PROMPT_VERSION` или `model_id` приводит к промаху кэша;
- тест деградации: при недоступности провайдера пайплайн доходит до конца, поля пусты, `RulesEnricher` не затронут.

## 9. Definition of Done

- [ ] `LLMEnricher` реализует `Enricher`, подключается конфигурацией без правок пайплайна
- [ ] вызывается только там, где правила вернули `None`
- [ ] `seawork eval enrichment` печатает отчёт §7 минимум по двум провайдерам
- [ ] доля ложных заполнений не выше 5% у выбранного провайдера
- [ ] проверка цитаты работает, тест на выдуманную цитату зелёный
- [ ] отключённый провайдер не ломает `ingest run`
- [ ] Batch-режим работает, кэш учитывает все три компонента ключа
- [ ] `tests/test_snapshot.py` и `tests/test_crewplanet.py` без регрессии
- [ ] `ruff`, `pyright`, `pytest`, CI — зелёные

## 10. Открытые вопросы

- окончательный выбор провайдера — по результатам §7;
- калибровка `confidence` для `inferred` — 0.6 предварительно, уточняется по точности из отчёта;
- нужен ли отдельный провайдер для пользовательского слоя (см. §3) — решается при проектировании AI-функций;
- имеет ли смысл LLM для `profession` на будущих источниках без структурированных полей — сейчас не нужен, 98.8% правилами.
