# Контракт адаптера: Crewplanet

> Реализует `sources/sites/crewplanet/` согласно `docs/modules/ingestion.md`
> Второй подключаемый источник. Данные проверены на живой ленте 19.07.2026, 158 вакансий

---

## 1. Зачем этот источник

Pinpoint дал 0% по зарплате и 0% по дате публикации (`docs/modules/source-pinpoint.md` §6). Crewplanet закрывает обе дыры:

| Поле | Pinpoint | Crewplanet |
|---|---|---|
| `salary` | 0% | **98.1%** |
| `posted_at` | 0% | **100%** |

Это не «ещё один источник для объёма». Это единственный проверенный поставщик данных, без которых Match Score не может ранжировать предложения по выгодности, а Delivery Engine — по свежести.

Дополнительно отрабатывается RSS-ветка `BulkSource`, не задействованная в Pinpoint.

## 2. Эндпоинт

```
GET https://www.crewplanet.eu/v2/en/vacancies/feed/rss
```

- авторизация не требуется
- формат RSS 2.0, элементы `<item>`, содержимое `description` — HTML с `<br />`
- пагинации нет, лента отдаёт полный текущий срез (~147 КБ, 158 записей)
- `Content-Type: text/xml`

**robots.txt проверен.** Запрещены `/v2/*/seaman/`, `/v2/*/princess_cruises/`, `/rus/employers/`, `/eng/seafarers/`, `/in_site/` и числовые пути `/1`…`/8`. Путь `/v2/en/vacancies/` под запрет **не попадает**.

### Реестр

```yaml
- platform: crewplanet
  source_id: crewplanet
  trust: primary
  direction: general_maritime    # см. data/reference/directions.yaml
  workplace_type_hint: vessel
```

### 2.1 Реестр требует правки — это часть задачи

Текущий `sources/registry.py` написан под единственный источник и второй не примет. Три изменения, все обязательные:

**`SourceConfig.account` сделать опциональным.**

```python
account: str | None = None
```

Поле осмысленно только для мультиарендных платформ вроде Pinpoint, где аккаунт задаёт поддомен. Crewplanet — отдельный сайт, аккаунта у него нет. Вписывать туда заглушку вроде `"crewplanet"` запрещено: это поле-идентификатор арендатора, а не имя источника, и мусор в нём собьёт логику построения URL.

**`RegisteredSource.source` перетипировать в протокол.**

Сейчас там жёстко `PinpointSource`. Нужный протокол уже существует — `ProcessingSource` в `ingestion/pipeline.py`, и оба базовых класса ему удовлетворяют. Переиспользовать его, новый не заводить.

**`build_source` перевести на диспетчеризацию.**

Сейчас всё, кроме `pinpoint`, отбрасывается через `raise ValueError`. Заменить на таблицу `platform → фабрика`. Подключение третьего источника должно стоить одной строки в таблице.

Проверка того, что рефакторинг удался: команды `ingest run`, `reprocess` и `report coverage` работают для обоих источников без ветвлений по имени источника в вызывающем коде.

## 3. Главная ловушка: `Salary:` встречается дважды

Поле `description` состоит из двух частей: свободного текста рекрутёра и **служебного хвоста**, добавляемого платформой. Хвост отбит табуляцией.

```
Requirements:
• Valid Second Engineer certificate
• Proven experience on transshipment vessels
Salary: Competitive, based on experience.        ← свободный текст

		Salary: 8 000 USD.                        ← служебный хвост
		Join date: 10.08.2026.
		Contract duration: 3 m.
		Send CV to cv12879130@gmail.com
		apply here: https://.../vacId/79130
```

У **19 из 158** записей `Salary:` встречается дважды. Наивный поиск первого совпадения по всему тексту вернёт для них `Competitive, based on experience` вместо `8 000 USD` — то есть потеряет ровно те данные, ради которых источник подключается.

**Правило: разбирать только служебный хвост, привязываясь к последовательности `Salary → Join date → Contract duration`, а не искать `Salary:` глобально.** Три поля идут подряд и присутствуют у 100% записей, что делает якорь надёжным.

Проверено: якорь по последовательности находит хвост у 158/158.

Свободный текст при этом сохраняется в `description` как есть — он содержит требования и описание судна, полезные для обогащения.

## 4. Маппинг полей

### Идентификаторы

| Наше поле | Источник |
|---|---|
| `external_id` | число из `vacId/{N}` в `<guid>` |
| `url` | `<link>` (совпадает с `<guid>`) |
| `content_hash` | sha256 канонизированного `<item>` |

### `NormalizedOpportunity`

| Наше поле | Источник | Покрытие | Примечание |
|---|---|---|---|
| `title` | `<title>` | 100% | `Barge Pilot for Cable lay vessel` |
| `description` | `<description>` без служебного хвоста | 100% | `<br />` → перевод строки, HTML вычистить |
| `posted_at` | `<pubDate>` | 100% | RFC 822, пример `Mon, 20 Apr 2026 11:50:53 +0300` |
| `salary_raw` | значение `Salary:` из хвоста | 100% | сырая строка до разбора |
| `employer` | — | 0% | в ленте отсутствует; `Shipowner:` встречается у 6% в свободном тексте |
| `location_raw` | — | ~5% | `Location:` встречается редко; работа судовая, см. §6 |
| `language` | детектор | — | лента англоязычная |

Служебный хвост из `description` **вырезается**: он дублируется в структурированных полях, а генерируемый адрес вида `cv12879130@gmail.com` — технический канал отклика, в тексте вакансии он мусор.

### Дополнительные структурированные поля

`Join date` и `Contract duration` из хвоста сохраняются в `source_fields` (`join_date`, `contract_duration`). Для Match Score они пока не используются, но это реальные факты источника, и терять их при нормализации незачем.

## 5. Разбор зарплаты

Наблюдаемые форматы (155 из 158 разбираются):

```
8 000 USD                 → min=max=8000,  USD, month
12 600 - 13 100 USD       → min=12600, max=13100, USD, month
350 USD per day           → min=max=350,   USD, day
205 EUR per day           → min=max=205,   EUR, day
up to 7 000 EUR           → min=None, max=7000, EUR, month   (3 записи)
```

Правила:

- разделитель тысяч — **обычный пробел**, не неразрывный;
- валюты в данных: `USD`, `EUR`; допускать также `GBP`;
- период: `per day` → `day`, иначе **`month` по умолчанию** — это допущение, поэтому `confidence` для таких значений ставить `0.8`, а не `1.0`, и `provenance=RULE`; при явном `per day` — `1.0`;
- `up to N` → диапазон только с верхней границей;
- нераспознанный формат (`Competitive`, свободный текст) → `salary = None`. Записывать нулевую или выдуманную сумму запрещено (`ingestion.md` §3.3).

## 6. География

Отдельного поля страны в ленте нет, `Location:` встречается у ~5% записей и содержит формулировки вида `Worldwide`.

Это **не дефект источника, а свойство отрасли**: работа судовая, у контракта нет страны в том смысле, в каком она есть у береговой вакансии. Та же ситуация была у Pinpoint (§3.1 его контракта).

Следствие: `country` остаётся `None`, и вопрос географии для судовых вакансий требует отдельного продуктового решения — вероятно, порт посадки или регион работы вместо страны. Выносится за рамки вехи.

## 7.1 Реализация

Базовый класс — **`BulkSource`** (`ingestion/sources/base.py`): лента отдаёт все записи одним запросом, ровно его случай. Наследовать, реализовать `collect()` и `normalize()`.

Размещение — `ingestion/sources/sites/crewplanet/`, поскольку Crewplanet это отдельный сайт, а не платформа с множеством арендаторов. Директории `sites/` пока не существует, создать.

`collect()` обязан вызвать `self._ensure_robots_allowed("/v2/en/vacancies/feed/rss")` до запроса, как это делает Pinpoint.

Разбор XML: `xml.etree.ElementTree` из стандартной библиотеки достаточно, дополнительная зависимость не нужна.
