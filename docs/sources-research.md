# Разведка источников

Проверено 19.07.2026, 28 сайтов. Метод: `robots.txt`, главная и карточка вакансии, поиск `application/ld+json`, отпечатки ATS-платформ, пробы API/RSS.

---

## Главный вывод: думать платформами, а не сайтами

Большинство работодателей не пишут карьерный раздел сами — они используют готовую ATS-платформу (систему управления наймом). У таких платформ, как правило, есть **публичный JSON API без авторизации**, потому что через него работает виджет вакансий на сайте клиента.

Отсюда смена стратегии подключения источников:

> Адаптер пишется не под сайт, а под платформу. Один адаптер Pinpoint открывает всех работодателей на Pinpoint — включая тех, кого мы подключим через год.

Это тот же принцип переиспользования, что и парсер JSON-LD, но сильнее: на выходе типизированный JSON, а не разобранный HTML.

Обнаруженные платформы среди проверенных сайтов: **Pinpoint** (2 круизных бренда), **Workable**, **Teamtailor**, **Phenom** (2), **Workday/SuccessFactors**, **WordPress/WP Job Manager** (3).

## Подтверждённые источники уровня 1

### 1. Pinpoint — `hollandamericagroup.pinpointhq.com` ⭐ рекомендован первым

```
GET https://hollandamericagroup.pinpointhq.com/postings.json
→ 200, application/json, 737 КБ, 93 вакансии, без авторизации
```

**Один эндпоинт покрывает несколько брендов Carnival.** Поддомены `princess.` и `seabourn.` отдают 404 — они не самостоятельны, вакансии лежат в аккаунте Holland America, бренд указан в `job.structure_custom_group_one`. Фактически в наборе **два** бренда: Holland America Line (69) и Seabourn (24). Princess в текущей выдаче отсутствует.

Заполняемость по 93 вакансиям:

| Поле | Покрытие |
|---|---|
| `title`, `description`, `url` | 100% |
| `employment_type` (типизирован) | 100% |
| `skills_knowledge_expertise` (квалификации) | 100% |
| `job.department` / `job.division` | 100% |
| `deadline_at` | 5% |
| `compensation_*` | 0% |
| дата публикации | **поля нет** |
| место работы | **непригодно, см. ниже** |

Поля зарплаты в схеме есть (`compensation_minimum`, `maximum`, `currency`, `frequency`), просто круизные компании их не публикуют.

**Поправка к первичной оценке.** Изначально `location.city` со 100% заполняемостью был засчитан как место работы — это ошибка. Во всём наборе лишь 8 уникальных значений `location.name` (`Global`, `India - CSSI`, `Philippines - UPL`, …), и это **рекрутинговые офисы Carnival**, а не места работы: вакансия повара с офисом в Мумбаи — это работа на судне. Пригодного `country` источник не даёт вовсе. Подробности и правило обработки — `docs/modules/source-pinpoint.md` §3.1.

Дата публикации отсутствует как поле, поэтому инкрементальный обход по дате невозможен, а новизна определяется на нашей стороне через `first_seen_at`.

`department` (`Galley`, `Guest Svc`, `Housekeeping`, …) и `division` (`Hotel`, `Technical`) — почти готовая классификация профессии.

**Trust: PRIMARY** — вакансии напрямую от работодателя.

### 2. Crewplanet — RSS

```
GET https://www.crewplanet.eu/v2/en/vacancies/feed/rss
→ 200, 147 КБ, 158 вакансий
```

Настоящий морской крюинг. В `description` шаблонный хвост, разбираемый правилом:

```
Salary: 550 EUR per day.
Join date: 15.10.2026.
Contract duration: 4 w.
```

**Зарплата присутствует** — единственный из проверенных источников, где она есть массово. Сертификаты упоминаются в тексте явно (`valid STCW documents`), что проверит нашу логику извлечения.

**Trust: PRIMARY** (крюинговое агентство, первичные вакансии).

### 3. Teamtailor — `careers.deepbv.nl`

Единственный сайт из всех 28 с **JSON-LD `JobPosting`**. Поля: `title`, `datePosted`, `description`, `employmentType`, `hiringOrganization`, `identifier`, `jobLocation`.

Один работодатель, вакансий мало, но адаптер Teamtailor переиспользуем.

### 4. Workable — `apply.workable.com/marinetraffic`

```
GET https://apply.workable.com/api/v1/widget/accounts/marinetraffic?details=true
→ 200, application/json
```

API работает и не требует авторизации, но **вакансий сейчас 0**. Держать в реестре: адаптер Workable пригодится для других работодателей.

## Рекомендуемый порядок подключения

| # | Источник | Тип | Что отрабатывает | Сегмент |
|---|---|---|---|---|
| 1 | Pinpoint (Holland America) | `BulkSource`, JSON API | базовый пайплайн на чистых типизированных данных | круизы, 2 бренда (HAL 63, SBN 24) |
| 2 | Crewplanet | `BulkSource`, RSS | RSS-ветка, разбор зарплаты и сертификатов | морской крюинг |
| 3 | PADI divejobs | `ListDetailSource`, HTML | HTML-ветка, фикстуры, `INTERNSHIP` | дайвинг, есть `/ru/` |

Три источника закрывают оба базовых класса, три разных сегмента индустрии и дают контрастные профили заполняемости — ровно то, ради чего пишется отчёт §8 спеки модуля.

Первым брать **Pinpoint**: он отвечает на главный вопрос вехи 1 (строится ли Match Score на детерминированных правилах) быстрее всех, потому что не тратит время на разбор вёрстки.

- **PADI** — закрытый `padijobs/v1` доказывает, что API существует
- **Indeed** — официальная партнёрская программа

## Разведка аккаунтов Pinpoint (задача B3, 20.07.2026)

Проверено **63 кандидата** по схеме `{account}.pinpointhq.com/postings.json` — круизные группы, экспедиционные линии, судовой менеджмент. Скрипт `scripts/probe_pinpoint_accounts.py`: честный User-Agent, чтение `robots.txt` перед эндпоинтом, пауза 1 с, отказ после первой неудачи по хосту.

**Найден один новый аккаунт.**

| Аккаунт | Вакансий | Состояние |
|---|---:|---|
| `hollandamericagroup` | 93 | подключён |
| `princesscruises` | **354** | **готов к подключению** |

Остальные 61 кандидат Pinpoint публично не используют: домен не резолвится либо эндпоинт не отвечает. Отдача низкая по числу попаданий, но одно попадание увеличивает корпус со 251 до 605 вакансий — рост в 2.4 раза ценой строчки в реестре.

### Princess Cruises — совместимость

- **Схема полей идентична** HAL, набор ключей совпадает полностью;
- `Content-Type` здесь `application/json`, у HAL был `text/html` — адаптер разбирает тело независимо от заголовка, правок не требует;
- `location.name` — снова рекрутинговые офисы (`Global`, `Philippines - MMC`, `Indonesia - PTAMI`), ловушка §3.1 подтверждается на втором аккаунте;
- `benefits` заполнено у 332 из 354 — правка вехи 1 окупается сразу;
- `compensation` заполнено у 2 из 354, `deadline_at` — у 0. Зарплат и дат по-прежнему нет.

### Покрытие обогащения — хуже, чем у HAL

| Поле | HAL | Princess |
|---|---:|---:|
| `profession` | 96.8% | **73.4%** |
| `experience_level` | 71.0% | **35.0%** |
| `required_certificates` | 48.4% | **22.6%** |

**Вывод, меняющий оценку задачи B4:** «адаптер платформы бесплатен» верно только про код. Справочники настроены на таксономию HAL, и на новом аккаунте они проседают. У Princess своя номенклатура департаментов — `Rooms Division`, `Photo`, `Stores`, `FB Svc`, `Shorex`, — а также отдельный дивизион `Japanese Language Shipboard Careers` (роли для японоговорящих на Diamond Princess). Подключение требует работы над `professions.yaml`, а не только строчки в реестре.

### Найденное улучшение правил

`RulesEnricher` сопоставляет профессию по `department`/`division`, а к заголовку обращается, только если департамент пуст. Если департамент заполнен, но не распознан, заголовок не пробуется вовсе — а он информативен (`Fitter Mechanic`, `Photographer`).

Замер фолбэка «департамент, затем заголовок»:

| Источник | По департаменту | По заголовку | С фолбэком |
|---|---:|---:|---:|
| Princess | 73.4% | 70.6% | **83.9%** |
| HAL | 96.8% | 71.0% | **97.8%** |

Улучшение на обоих аккаунтах, регрессии нет ни на одном. Требует проверки на ложные срабатывания перед внедрением.
