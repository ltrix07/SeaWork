# Журнал замеров согласия Match Score с разметкой

> Дописывается командой `seawork eval match report <файл> --log`. Записи не переписываются и не удаляются: замер имеет смысл только тогда, когда следующий можно сравнить с предыдущим в неизменном виде.
>
> Что меряется и по какому эталону: `docs/plans/match-gold/plan.md`, `tests/fixtures/eval/match_gold.yaml`. Порога в коде нет: абсолютный процент согласия нельзя интерпретировать, пока веса не откалиброваны.

## Как читать

**Оценка пересчитывается на замороженных вакансиях в момент отчёта.** Замер меряет формулу такой, какой она была в коде в этот день, а не той, по которой пары отбирались. Между двумя записями журнала могли поменяться веса; запись это не фиксирует, дату сверяйте с историей `scoring/`.

**Порядок повторяет порядок выдачи.** Для каждого профиля берутся пары (вакансия «подходит», вакансия «не подходит»), которые обе попадают в выдачу, то есть `value != 0.0`. Ключ сравнения тот же, что у `recommend` (`rank_tier`): положительное значение выше `None`, затем больший `value`, затем больше сравнимых факторов. Свежесть и id не учитываются. «Подходит» должна встать строго выше; полное равенство ключа это ничья, в доле она весит половину (как в AUC), число ничьих печатается. `None` у «подходит» против положительного «не подходит» это ошибка порядка. Сравниваются только вакансии одного профиля, группа суммирует сравнения своих профилей.

**Исключение из выдачи (`value=0.0`) считается отдельно, в порядок не входит.** «Не подходит» с `0.0` это верное исключение (доля от «не подходит»). «Подходит» с `0.0` это ошибка, и самая дорогая: вакансия не дойдёт до человека (доля от «подходит»).

**`None` у «подходит».** Считается только по профилям с фактами. У профилей без фактов (`empty`, `browsing`) `None` структурный и от формулы не зависит; они помечены `structural_none` в `match_profiles.yaml`. Нет «подходит» в группе: прочерк, не 0.

**«Спорно»** в бинарные метрики не входит, считается отдельно.

**Группы профилей.** «Форма онбординга» повторяет то, что бот знает о человеке сейчас (этап, направления, страна оформления). «Расширенный профиль» описывает будущую аудиторию с профессиями, сертификатами и целью: замер отвечает, как оценка поведёт себя, когда профиль станет полнее. Группа задаётся полем `kind` в `tests/fixtures/eval/match_profiles.yaml`.

**Расхождения** печатаются с факторами: `+` совпал, `-` не совпал, `?` не сравним, в скобках caveats.
